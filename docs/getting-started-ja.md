# はじめかた — Thinreports の表機能を使う・改造する

このドキュメントは、**Claude Code を使って** Thinreports の表(table)機能を動かし、
自分で改造できるようになるまでの手順です。

**git や GitHub の知識は要りません。** 作業はすべて Claude Code にお願いします。
あなたがやるのは「フォルダを作る」「文章を貼り付ける」だけです。

---

## 0. 先に知っておいてほしいこと

### 用語のミニ辞典

読み飛ばしても大丈夫です。出てきたときに戻ってきてください。

| 言葉 | 意味 |
|---|---|
| リポジトリ | プログラムの入れ物。GitHub 上の1プロジェクト |
| fork（フォーク） | 他人のリポジトリを自分のアカウントに複製すること。GitHub の web でボタン1つ |
| clone（クローン） | リポジトリを自分のパソコンに持ってくること |
| ブランチ | 同じリポジトリの中の「別の作業線」。今回の表機能は `feature/table-item` というブランチにあります |

### Thinreports は3つのプログラムでできています

```
エディタ（アプリ）  ──保存──▶  .tlf ファイル  ──読み込み──▶  Generator（Ruby）  ──▶  PDF
```

| リポジトリ | 役割 | 今回使うか |
|---|---|---|
| `thinreports-section-editor` | **表を作るエディタ**（Section Format 用） | **使う** |
| `thinreports-generator` | PDF を作る Ruby ライブラリ | **使う** |
| `thinreports-basic-editor` | 旧来の Basic Format 用エディタ | **使いません** |
| `thinreports` | 説明用のドキュメントだけ | 使いません |

> **注意:** もし `thinreports-basic-editor` を fork していても、今回は使いません。
> 表機能は **Section Format** という新しい形式のもので、そちらは
> `thinreports-section-editor` で作ります。

## 2. コードを手元に持ってくる

### 2-1. 作業用のフォルダを作る

どこでもいいので、空のフォルダを1つ作ってください。例：

```
C:\thinreports
```

### 2-2. そのフォルダで Claude Code を起動する

> Claude Code は「起動したフォルダ」がそのまま作業場所になります。
> 必ず、いま作ったフォルダで起動してください。

### 2-3. 次の文章をそのまま貼り付ける

```
次の2つのリポジトリを、このフォルダの下に clone してください。
どちらも feature/table-item ブランチを使いたいです。

- https://github.com/tarosay/thinreports-generator
- https://github.com/tarosay/thinreports-section-editor

clone が終わったら、それぞれのフォルダにある CLAUDE.md を読んで、
何のプログラムなのか私に説明してください。
```

これで手元にコードが揃います。

## 3. 動かせるようにする

### 3-1. PDF を作れるようにする

`thinreports-generator` のフォルダで Claude Code を起動し直して、これを貼ります。

```
CLAUDE.md を読んで、このリポジトリの開発環境を作ってください。
Ruby が入っていなければ、バージョンを切り替えられる形で入れてください。
終わったら test/section_report/features/table/ のテストを実行して、
結果を教えてください。
```

> **時間がかかります。** Ruby のインストールから始まると 10〜20 分ほど見てください。

### 3-2. 表の PDF を実際に出してみる

```
test/section_report/features/table/ のテンプレートを使って、
表が入った PDF を作ってください。作ったら開いて見せてください。
```

罫線つきの表が出れば成功です。

### 3-3. エディタを起動する

`thinreports-section-editor` のフォルダで Claude Code を起動し直して、これを貼ります。

```
CLAUDE.md を読んで、このアプリの開発環境を作って、起動してください。
```

アプリのウィンドウが開いたら、**ツールバーの右端にある表のアイコン（田の字）**を選んで、
キャンバスの上をドラッグしてみてください。表ができます。

## 4. 表の使い方

### エディタでの操作

| したいこと | やり方 |
|---|---|
| 表を作る | ツールバーの表アイコン → キャンバスをドラッグ |
| 表全体の設定 | 表の枠をクリック → 右のプロパティで列の追加/削除、列の幅、既定の罫線 |
| 行の設定 | 表の左端に出る細いグレーの帯をクリック → 種類・高さ・自動伸縮・並べ替え |
| セルの設定 | セルを直接クリック → 背景色、網掛け、余白、罫線、セル結合、セルの中身 |

### 行の3つの種類

| 種類 | いつ出るか |
|---|---|
| header | 表の先頭に1回だけ |
| **body** | **データの件数だけ繰り返される** |
| footer | 表の末尾に1回だけ（合計行など） |

明細行は必ず **body** にしてください。

### Ruby から値を流し込む

明細のセルの中身を「text-block」にして、ID を付けておきます（既定では列の ID が入ります）。
そのうえで、こう書きます。

```ruby
items: {
  items: {                        # 表の ID
    rows: [
      { id: 'detail', cells: { name: 'りんご', qty: 3, price: 120 } },
      { id: 'detail', cells: { name: 'バナナ', qty: 12, price: 20 } },
      { id: 'total',  cells: { total_price: 600 } }   # footer 行に合計を入れる
    ]
  }
}
```

分からなくなったら、Claude Code にこう聞けば済みます。

```
docs/table-item.md を読んで、この表に値を流し込む Ruby のコードを書いてください。
テンプレートは <保存した .tlf のパス> です。
```

## 5. できること・できないこと

### できること

- 列を定義する（ID と幅）
- 罫線を自動で引く（セルごとに4辺を指定できる）
- **行の高さが内容に応じて伸びる**（長い文字が入ると、その行だけ高くなる）
- セルを結合する（横・縦）
- セルを塗りつぶす・網掛けする

### まだできないこと

ここは**改造の出発点**でもあります。

- **表がページを跨げません。** 1ページに収まらない分ははみ出します
- セル結合と列幅は数値で入力します（ドラッグで操作できません）
- 行の自動伸縮は、エディタの画面上では再現されません（PDF では効きます）
- セルの中に置けるのは1つだけです

## 6. 改造をはじめる

**改造もすべて Claude Code に頼めます。** 大事なのは「まず設計ドキュメントを読ませる」ことです。

```
docs/table-item.md を読んでください。
そのうえで、<やりたいこと> を実現するには、どこをどう直せばいいか教えてください。
まだコードは変更しないでください。
```

説明を読んで納得できたら、

```
その方針で実装してください。テストも追加してください。
```

### 改造のお題の例

```
表がページを跨げるようにしたい
```

```
列の幅を、境界をドラッグして変えられるようにしたい
```

```
セルの中に画像を置けるようにしたい
```

### ⚠ 必ず知っておくべき落とし穴

**エディタと Generator は、`.tlf` というファイルの形だけでつながっています。**
片方だけ直すと、もう片方が読めなくなります。

- エディタに新しい設定項目を足したら → **Generator にもそれを読む処理が要る**
- Generator に新しい機能を足したら → **エディタにもそれを設定する画面が要る**

Claude Code にはこう伝えてください。

```
この変更は .tlf のスキーマに影響しますか?
影響するなら、もう一方のリポジトリで直すべき箇所も教えてください。
```

## 8. うまくいかないとき

まず、そのエラーメッセージをそのまま Claude Code に貼ってください。たいてい解決します。

それでも詰まりやすい既知の問題を挙げておきます。

### `Could not verify the SSL certificate` と出る

セキュリティソフト（Avast など）が通信を検査していると起きます。
Windows は信頼している証明書を、Ruby が知らないのが原因です。

```
Ruby が rubygems.org の証明書を検証できません。
セキュリティソフトが HTTPS を検査している可能性があります。
原因を切り分けて対処してください。
```

### `Ruby >= 3.3.0 is required` と出る

Ruby が古いです。

```
Ruby のバージョンが古いようです。3.3 以上を入れて切り替えてください。
```

### テストが「0 failures」なのに何も検証されていない

PDF を比較する `diff-pdf` というコマンドが無いと、テストは飛ばされます。
**skip の数を必ず確認してください。**

```
テストの skip 数を確認して、実際に検証されたか教えてください。
```
